# 我到底要怎么用

这份文档回答一个具体问题：**装好之后，我第一步做什么、第二步做什么。**
不涉及设计动机（那在 `00-m0-scope.md` 和 `03-m1-scope.md` 里）。

---

## 0. 先说清楚一件事：它是账本，不是仪表盘

这是最容易产生期待落差的地方，所以放在最前面。

**当前版本不会自动去任何平台帮你抓用量。** 它的真实数据入口只有一个——
你把一个 CSV / JSON 喂给它。除此之外：

| 你想要的 | 现在能不能 |
|---|---|
| 手动导入 CSV / JSON 用量与收费 | ✅ 完全可用，有去重与行级报错 |
| Codex CLI 用量探针 | ⚠️ 代码已实现，但**从未在真实客户端跑通**，且需要外网 |
| ChatGPT 用量导出 | ❌ 没有。`conversations.json` 解析属于 M2 |
| Cursor 用量 / 费用 | ❌ 未实现（M1 剩余） |
| 自动定时同步 | ❌ 没有，也不在 M1 范围 |

所以它的定位是：**一个口径严格的手工账本 + 记忆交接工作台。**
价值不在「自动同步」，而在「把散在四个客户端的东西按同一套口径放在一起，且不会算错」。

如果你期待的是「装上就能看到我这个月花了多少钱」——那现在做不到，
而且我不想让界面假装做到了。

## 1. 三步跑起来

```bash
npm install
npm run build
npm start
```

启动后终端会打印一行**黄色配对码**（例如 `配对码：XE397GHG`）。
浏览器打开 `http://127.0.0.1:8787`，把这个码填进去。

> 配对码是一次性的，配对成功后立即更换。
> 服务只监听 `127.0.0.1`，但「只监听本地」不等于「只有你能调用」——
> 你打开的任何网页都能向 localhost 发请求，所以需要这一步。

**起不来先看这个**：

- `端口 8787 已被占用` —— 上一个实例还在跑（关终端窗口不会结束进程）。
  换端口：`AICC_PORT=8788 npm start`（PowerShell：`$env:AICC_PORT=8788; npm start`）。
- `界面打不开但服务在跑` —— 先 `npm run build`，服务端只提供 `apps/web/dist` 里的静态资源。
- 终端中文乱码 —— 先执行 `chcp 65001` 再启动。

## 2. 第一步：先登记，再导入

顺序不能反。**导入时可以选「归属账户 / 项目 / 客户端」，但那些得先存在。**

到「设置与连接 → 登记」，建三样东西：

1. **客户端**（你在用什么工具）：`Codex CLI` / `Cursor` / `ChatGPT 桌面端` / `ChatGPT 网页端` / `WorkBuddy` / `自建 API Agent`。
   类型有下拉，**只有这几种**——填 `codex_cli` 这种自造值会被拒绝（我试过，会返回合法枚举）。
2. **计费账户**（钱从哪个账户出）：`provider` 填 `openai` / `anthropic` / `cursor` 等，
   `alias` 是你自己看得懂的名字。
   注意：账户表**没有凭据字段**，这里不填也不会填任何密码 / Cookie。
3. **订阅**（可选）：月费、币种、计费周期。金额填 `19.99`，
   提交前会转成定点整数并存 `"1999"` —— 中间值会显示给你核对，避免浮点误差。

## 3. 第二步：把数据喂进去

到「用量与费用 → 导入数据」。**先点「预检（不写库）」**，它会告诉你有多少行会被判为重复。

### 用现成模板

仓库里有三个，直接用 Excel / 记事本填：

| 文件 | 用途 |
|---|---|
| `templates/usage-template.csv` | 用量（token） |
| `templates/charges-template.csv` | 收费（钱） |
| `templates/usage-template.json` | 用量 JSON 格式 |

模板是 UTF-8 **带 BOM** 的，Excel 打开中文不会乱码；解析器会自动去掉 BOM（已实测）。

### 列名白名单

**列名必须是下面这些之一，否则该列会原样保留进 `raw_usage` 但**不参与统计**——
系统不会按名字相似度去猜，猜错的代价是一条看起来正常的假数据进了主库。**

用量 CSV：

| 你要表达的 | 接受的列名 |
|---|---|
| 时间（必填） | `occurred_at` / `timestamp` / `time` / `datetime` / `date` / `created_at` |
| 请求 ID（**强烈建议填**） | `request_id` / `provider_request_id` / `id` / `trace_id` |
| 模型 | `model` / `model_name` / `model_id` |
| 输入 token | `input_tokens` / `prompt_tokens` / `input` |
| 输出 token | `output_tokens` / `completion_tokens` / `output` |
| 缓存 token | `cached_tokens` / `cache_read_tokens` |
| 推理 token | `reasoning_tokens` / `thinking_tokens` |
| 总 token | `total_tokens` / `total` |
| 项目 / 客户端 | `project` / `client` |

收费 CSV：`occurred_at`、`amount`、`currency`、`kind`、`status`、`billing_ref`、`period_start`、`period_end`、`note`。

### 关于 `request_id`：这是去重能生效的关键

我实测过同一份 CSV 导入两次的结果：

```
第 1 次：新增 2 行
第 2 次：新增 0 行，重复来源留证 2 行   ← 不会翻倍
```

**但这是在有 `request_id` 的情况下。** 没给稳定请求 ID 时，系统无法确认「这两行是不是同一个请求」，
会把它们标为**待确认重复**——既不静默合并，也不静默丢弃，要你自己去「用量」页确认。

所以：**能给 `request_id` 就给**，它能把「待确认」变成「确定重复」。

## 4. 第三步：看懂它算出来的数

四条规则，不知道这几条会觉得数字算错了：

1. **未知就是 `null`，不是 0。** 供应商没报 token 就留空。
2. **缓存和推理是子项，不重复相加。** 输入 10,000（含缓存 6,000）+ 输出 2,000（含推理 1,000）
   = **12,000**，不是 19,000。
3. **额度、汇总、明细三者永不互相相加。** 额度是快照，到了重置时间没重新查询就显示「待刷新」，
   **不会自动按 100% 算满**。
4. **费用按币种分行**，不做跨币种相加。

所以首页**没有「总消耗」这一个数字**——只有按口径分开的几组。这是刻意的。

## 5. 记忆怎么用

到「记忆」页。核心一条：**AI 只能提案，批准是你一个人的动作。**
代码里不存在「直接写入一条生效记忆」的路径，正式记忆只能由 `approve` 产生。

流程：在你的 ChatGPT / Claude / 任何客户端里让 AI 生成候选 → 粘进来 → 你审核批准。
本版本**没有内置 AI 提炼**（不在 M0 / M1）。

两个防呆：

- **更新必须带基线版本。** 两个客户端基于同一旧版本改，第二次审批返回 409 冲突，不会「最后写入者获胜」。
- **删除留墓碑**（只含哈希），防止旧导入包把已删内容复活。删除报告会如实列出
  「不随本次删除消失」的东西：你复制到别处的文本、其他平台的原生记忆、你自己的备份。

## 6. 进阶：把 MCP 挂到客户端（**未验证**）

这一步**从未在任何真实客户端里跑通**。传输层和六个工具都有端到端测试
（真起子进程、真走 TCP、真验证权限隔离），但没在你的 Codex / Cursor 里挂过。
所以「能力登记」页那一项仍然显示 `documented`，不会自己变成「已同步」。

想试的话：

1. 服务保持运行。
2. 「设置与连接 → 代理凭据」签发一个凭据，**明文只显示一次**。
3. 在客户端里配：

```bash
AICC_TOKEN=<你的凭据> node apps/mcp/dist/index.js
```

只认两个环境变量：`AICC_TOKEN`（必填）和 `AICC_API_URL`（默认 `http://127.0.0.1:8787`）。

> **已踩过的坑**：codex 的 `config.toml` 里若有 `service_tier="default"`，
> 0.130.0 会判整个配置无效并放弃读取它——于是 `codex mcp add` 写进去的 MCP 项也不生效。
> 先修那一行再配。

**试完请告诉我结果**，那才是 M1 最后一步的验收证据。

## 7. 数据在哪、怎么备份

- 数据库默认 `data/ai-control-center.sqlite`（`AICC_DATA_DIR` 可改）。**`data/` 已在 `.gitignore`。**
- 备份：「设置与连接 → 备份与恢复」一键操作，或直接复制 `data/backups/` 下的目录。
- 演示数据带「【示例】」前缀且 `is_demo=1`，**不计入任何真实统计**；
  界面上有「真实 / 示例 / 全部」三态切换。

常用环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `AICC_PORT` | `8787` | 监听端口 |
| `AICC_HOST` | `127.0.0.1` | 改成别的值会被**拒绝启动** |
| `AICC_DATA_DIR` | `./data` | 数据目录 |
| `AICC_TZ` | `Asia/Shanghai` | 展示时区（存储一律 UTC） |
| `AICC_ALLOWED_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | 允许调用写接口的来源 |
| `AICC_CODEX_COMMAND` | `codex` | Codex 探针调用的命令名 |
