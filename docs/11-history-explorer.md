# v0.4 会话、工作区与联动分析

总览保留官方／本地统计选择，新明细只回答本机已记录的会话用了多少 Token、归属哪个项目目录、使用哪些模型。官方账户累计不分摊到目录，不要求本机明细之和等于官方累计。

## 页面

会话列表每页 50 条，默认按最近用量降序，支持标题／标识／目录搜索以及 Token、名称排序。详情展示明确标题、完整会话标识、项目目录、范围内首末用量时间、Token 子项、趋势与模型分布。没有用量的空会话不生成明细，首末时间不表示工作时长。

工作区按会话明确记录的初始项目目录归属。同一 Windows 目录统一大小写、分隔符、尾部斜杠后跨来源聚合，展示保留原目录；POSIX 路径保留大小写。子目录、Git worktree、符号链接不自动合并。未记录绝对目录的会话归到未归属工作区，历史日志存放目录不当作项目目录。目录卡片点击进入该目录的统计及会话列表。

分析提供日／周／月趋势、来源／模型分组、折线／堆叠柱状图，以及工作区×模型热力图。周从周一开始。热力图显示当前条件下前 20 个工作区×前 10 个模型，可切换完整表格分页查看；点击单元格进入关联会话。

三个明细页面共用来源、工作区、模型、UTC 日期与搜索条件；日期只累计范围内记录，跨日期会话不会整段计入。未知日期纳入全部历史但不绘入趋势，指定日期时排除并提示。缺失不补零，输入包含缓存子项、输出包含推理子项。缓存比例按有效配对记录加权，缺失覆盖显示部分记录。Codex 上游分项负差分仍保留。

页面、筛选、排序、分页及详情 ID 保存在 URL hash；搜索词仅存在当前组件状态。完整刷新默认真实数据，示例数据需要重新选择。过期请求不能覆盖最新筛选，切换页面时旧结构也不会用于渲染新页面。

## 采集与本地存储

SQLite v2 新增 `history_detail_source`、`history_detail_session`、`history_detail_bucket`。用量保留到会话×UTC 日期×模型分桶，含字段覆盖计数及输入／缓存配对样本。身份由来源、配置范围和源会话标识派生。没有将历史明细写入旧的项目管理表，也不复制聊天正文。

- Codex：复用去重、分叉继承排除、累计重置和分项修正后的差分。目录来自首个会话元数据，标题来自明确元数据及可选 `session_index.jsonl`。缺少标题索引不影响用量扫描。
- WorkBuddy：复用已去重的请求；仅读取顶层明确标题和 cwd。缺少 sessionId 的兼容文件身份使用哈希，不保存源文件路径。
- OpenCode：复用步骤／消息统计口径；存在支持的 session 表时，只选择 id、title、directory。缺少元数据表时仍可统计用量。
- MiniMax Code：复用 canonical messages.jsonl 的去重结果；明确会话标题和 cwd 可用时保存，缺失时保持未知。
- DeepSeek 账单与无关联的通用导入仍只参与总览，不推断会话。

汇总响应继续只有聚合结果；采集中的明细通过内存关联移交持久化，不进入 app_settings 或首页载荷。每个来源的明细、汇总和同步状态同事务提交，成功重扫替换而非追加。失败保留同配置旧明细并标记 stale；配置变化不继承旧目录记录；成功空扫描清空。Codex 明细成功状态独立于官方接口状态，官方成功不能掩盖本机扫描失败。旧库升级不反推记录，需同步建立索引。

全部明细来源沿用本地口径的来源排除规则，单独查看被排除来源不改变合计规则。跨来源同目录聚合不代表跨平台逐请求去重。

本机索引保存会话标识、标题、项目目录和统计数字，不保存聊天正文、工具参数、凭据或历史日志文件绝对路径。标题不从聊天首句提取。这些元数据会包含在数据库备份中。示例索引仅含合成数据，清空示例时级联清除分桶。

## HTTP 接口

新增 `GET /api/history/sessions`、`/api/history/sessions/:id`、`/api/history/workspaces`、`/api/history/workspaces/:id` 和 `/api/history/analytics`。全部只读缓存、使用同一读取事务、返回 `Cache-Control: no-store`，仅用户会话可访问；匿名和代理凭据不能读取。`workspace=demo` 仍代表示例隔离，新目录条件为 `workspaceId`。

通用参数：`source`、`workspaceId`、`model`、`from`、`to`、`q`、`page`、`sort=recent|tokens|name`、`direction=asc|desc`。分析另支持 `granularity=day|week|month`、`split=source|model`。日期验证真实日历日及起止顺序；查询使用绑定参数。列表每页 50 条，summary 是完整筛选结果；分析矩阵表格也分页，topRows 单独提供有限热力图单元。

响应 context 提供来源纳入原因、索引状态、元数据覆盖数量及可筛选目录／模型。详情不存在或被当前筛选排除返回 404。纯缓存 GET 不触发采集；首页不查询会话表。

## 验证

`npm run verify:all` 覆盖现有统计、SQLite 迁移、明细交叉核对、权限、事务回滚、备份恢复、空结果和旧缓存兼容。`npm run verify:desktop` 用真实 Electron 和隔离合成数据检查页面切换、详情、分页、URL 返回／刷新、搜索、矩阵下钻、请求竞态与 390／1000px 布局；截图在 `tmp/desktop-verification/explorer-*.png`。

`npm run verify:explorer` 构造一万会话、十万分桶，验证汇总一致、50 条分页、查询中位耗时小于 3 秒和响应小于 300 KB；报告在 `tmp/explorer-performance.json`。这是本机合成基准，不代表所有硬件或所有真实来源格式。发布另外执行 `npm run verify:release`，在项目外运行解包目录与便携 EXE。
