```bash
npm run verify:sqlite     # SQLite 驱动最小兼容性验证（写业务代码之前跑的）
```

### 2.1 关于 SQLite 驱动的实测结论

`better-sqlite3` 在本机没有可用的预编译包，需要 MSVC 现场编译，因此固化下来用的是
Node 22 内置的 `node:sqlite`。它的 `DatabaseSync` 是同步 API，`exec` / `prepare` / `run` / `get` / `all`
的形状与 `better-sqlite3` 接近，所以 `db/database.ts` 用一层适配把它包起来，换驱动不需要改业务代码。

两个必须注意的差异（都已在适配层处理）：

- **参数绑定只接受 `null` / `number` / `bigint` / `string` / `Uint8Array`。**
  传 `boolean` 或 `undefined` 会直接抛 `TypeError`。适配层在 `toBind` 里统一收敛。
- **查询返回的是 null 原型对象。** `assert.deepEqual` 直接拿它跟对象字面量比较会失败，
  测试里需要先 `{...row}` 摊平。

## 4. 测试之外还做了什么

### 4.1 真实 HTTP 冒烟（`npm run verify:smoke`）

验收测试用的是 Fastify 的 `inject`，它跳过真实 socket、Host 头、Cookie 收发与静态资源服务。
所以额外写了一个冒烟脚本：**真的 spawn 服务进程、真的在 127.0.0.1 上发请求、真的从终端 stdout 解析配对码**。

它额外覆盖了这些东西：

- 服务端直接提供已构建的前端页面（而不是占位页）
- Cookie 的 `HttpOnly` / `SameSite=Strict` 设置能跨真实 HTTP 往返
- 配对码一次性：同一个码重放会被拒
- 真实网络路径下重复导入的幂等性
- 代理凭据在真实网络下的项目范围隔离与审批拒绝

**这个脚本抓到了两个进程内测试没覆盖到的真实缺陷**：空 JSON 请求体被包成 500，
以及 `tx()` 不可重入（详见 `01-invariants.md`）。

### 4.2 测试没抓到、由「自己用一遍」抓到的缺陷

**示例数据生成之后什么都看不见。**

验收测试全部通过 —— 因为测试断言的是「示例数据不污染真实统计」，
而这个实现确实做到了（做过头了）：它把所有视图里的 `is_demo = 1` 都排除了。
于是用户点了「生成示例数据」，界面上依然一片空白。

设计稿 §8 的原话是「演示数据使用**单独的 demo workspace** 和持续可见的标识，
**不能污染真实总览**」—— 这是两件事，实现只做了后半句。

现在改为三态工作区范围（`real` / `demo` / `all`）：真实视图里一行示例都不出现，
示例视图里能看到全部示例且不含真实数据，默认不传参数时为真实。
前端顶栏可切换，并且由 API 客户端统一给所有读取带上参数，
避免出现「概览是示例、明细是真实」这种最难排查的混搭。

**教训**：测试能验证「我写下的断言」，验证不了「我漏掉的意图」。
设计稿里的每一句话都值得对照检查一遍，尤其是那种**看起来已经被满足**的句子。

### 4.2.1 由「用户实际使用」抓到的缺陷

**端口被占时只给一段 `EADDRINUSE` 堆栈。**

上面四条自动化路径全都没覆盖它 —— 它们各自启动服务时都独占着一个空闲端口，
「端口已经被别人占着」这个状态从没被构造出来过。

修复：把端口探测提到打开数据库之前（失败得早，且不碰数据库），
识别出该错误后打印分步骤的排查指引（查占用进程 / 结束进程 / 换端口启动），
并在启动失败时关闭已打开的数据库。
回归测试在 `apps/server/test/startup.test.ts`：空闲放行、被占抛出、
提示可执行、探测不把自己变成占用者。

**教训**：环境前提（端口、磁盘、权限）拿到之前的一切乐观假设，都要有一条测试真的把它破坏掉。

### 4.3 没做的事

- 没有在真实的 Codex / Cursor / WorkBuddy / ChatGPT 账户上验证任何接口 —— 那是 M1 的工作，
  且必须逐账户逐客户端实测。本版本所有集成的能力状态保持 `documented` 或 `unknown`。
- 没有做性能基准。设计稿 §15 提到「10,000 条记忆 + 100,000 条用量观测，列表与搜索 p95 < 500 ms」，
  这是**待测目标**，本文不声称达到。
- `getRevision` 与 `listQuotaHistory` 目前只有仓储层实现，没有独立的 HTTP 用例覆盖。
