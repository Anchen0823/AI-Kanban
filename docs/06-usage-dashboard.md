# 历史用量统计

首页「用量总览」优先显示历史累计 Token，当前额度与余额在下方折叠区。

最上方「全部 AI 累计 Token」合计已接入来源的已知总量。同步 Codex 或重新读取 DeepSeek 导出后，总面板自动更新。来源与纳入情况可展开查看；缺失数据不会冒充零，缓存和推理不再次加总。通用导入若可能与已有专用数据重叠，会暂不计入并说明原因。

后续数据源统一通过 `HistoryTotalCandidate` 接入服务端汇总，界面由 `sources` 列表自动展示，无需为每家供应商重写总面板。仅提供独立、不重叠的总量；遇到重叠来源应声明统计优先级或先完成记录级去重。

## Codex 历史

点击「同步 Codex 历史」，读取 `CODEX_HOME`（未设置时为用户目录下 `.codex`）里的现存及归档会话日志。统计只保留用量聚合，不保存聊天正文。再次同步更新已有统计，不将累计计数逐条相加。

可以展开模型、日期明细和数据范围。缓存输入已经包含在输入内，推理输出已经包含在输出内，不能再加一次。日期明细按 UTC 分日。

这是本机保留历史的累计值，不保证覆盖其他设备或已经删除的日志；没有数据时显示未知，不显示虚构的零。缺失字段、无法读取或无法确定归属的记录会在数据范围中提示。

## DeepSeek 控制台历史

将控制台下载的 `usage_data_*.zip` 放进同一个文件夹。在首页 DeepSeek 卡片点击「读取控制台导出」，填入文件夹完整路径，再点「读取并统计」。原文件保持不变，支持 ZIP 内 `amount-*.csv` / `cost-*.csv` 及直接放置的 CSV。

Token 明细按缓存命中、缓存未命中、输出分别统计；输入为命中与未命中之和。请求次数单独显示。消费金额来自 `cost` 文件，按币种累计，保留原始精度；不会以余额变化或当前单价估算历史消费。

相同明细在多个导出中出现时去重；相同计费项数值不一致时显示冲突提示。统计只覆盖文件所包含的时段，中间缺月不会补成零。API Key、用户标识等原始字段仅参与内存中的去重，不进入聚合缓存或页面。

## 其他 API 历史

「用量记录 → 导入数据」支持 CSV / JSON，先预检再导入。选定 DeepSeek 账户，或使用明确的 `deepseek-*` 模型名，可在首页按供应商显示累计用量。已有的稳定请求 ID 用于去重。

CSV 示例：

```csv
request_id,timestamp,model,prompt_tokens,completion_tokens,total_tokens,prompt_cache_hit_tokens
example-1,2026-09-01T08:00:00Z,deepseek-chat,1000,200,1200,800
```

JSON 可以是记录数组；支持 DeepSeek 原生响应中的 `id`、`model`、`created` 和嵌套 `usage` 计数。这里只累计导入的历史，与本机 Codex 单独展示，避免重复计算同一份用量。记录没有日期时，归入未知日期。

DeepSeek 官方公开的 [余额接口](https://api-docs.deepseek.com/api/get-user-balance/) 返回当前余额；[Token 用量文档](https://api-docs.deepseek.com/quick_start/token_usage/) 说明单次请求的实际计数来自响应 `usage`。历史接入使用控制台导出或已保存的 API 响应；没有历史记录时不会声称已获取全账户用量。

## 当前额度和余额

- Codex：展开「当前额度与余额」后检测，读取本机 Codex CLI 已登录账户的窗口剩余比例和重置时间。CLI 未登录时会提示检测失败；历史日志统计不依赖这一步。
- DeepSeek：点击「连接」输入 API Key，或在启动服务前设置环境变量 `DEEPSEEK_API_KEY`。密钥只保存在服务运行期间的内存中，不存入数据库或浏览器存储；服务重启后需重新连接，环境变量方式除外。
- 两者均为只读查询，不发起付费模型推理。失败时保留上次成功结果并标明状态和时间。额度与余额不参与 Token 累计。

## 验证边界

余额接口的成功、错误、超时、金额精度以及历史导入通过本地 fixture 验证。没有用户真实 DeepSeek Key 时，不能据此声称真实账户已连接。
