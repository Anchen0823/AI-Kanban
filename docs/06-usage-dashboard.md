# 历史用量与同步规则

v0.4 新增会话、项目目录和联动分析，详见 [明细说明](11-history-explorer.md)。以下总览口径继续保留；总览时间控件仅影响总览趋势，新明细页面的筛选作用于其全部指标。独立本机索引保存明确的会话标题、标识和目录，汇总缓存仍保持脱敏。

## 数据来源

Codex 同步首先尝试本机 CLI 的 `account/usage/read`；官方累计与每日趋势分别采用返回值，缺失项回退本机日志。官方累计不与本机累计相加，也不由每日记录补算。官方会话估算明细完整且与累计核对一致时，输入、输出、缓存与模型采用官方明细，否则继续使用独立的本机明细。推理字段缺失保持未知，不按比例补齐。

官方查询要求 Codex CLI 使用 ChatGPT 登录；运行 `codex login` 并选择对应账号。未登录、不支持或超时均明确显示回退原因。官方失败时不恢复旧官方账户累计。Windows 自动查找原生 CLI，显式 `AICC_CODEX_COMMAND` 优先。

WorkBuddy、OpenCode、MiniMax Code 只读扫描本机保留的日志或数据库，不保证覆盖其他设备和已删除记录。DeepSeek 从用户选定的 ZIP/CSV 导出目录读取，统计缓存只保留聚合结果与脱敏同步信息；成功选择的目录单独保存在本机设置中，仅在已配对用户的真实工作区返回。

## 快照、失败与覆盖

各来源分开保存最近有效快照和最近同步尝试。相同来源配置下，路径缺失、权限失败或数据库损坏不会覆盖有效快照；GET 返回旧数值和原成功时间，`sync.stale` 为 true，`lastAttempt` 记录失败。POST 的 `status` 仍描述本次尝试。明确成功的空扫描可以更新为空，未知不改成零。

本机配置变化后不能继承旧路径的快照。DeepSeek 会记住成功读取的目录并在重启后自动填入；失败的目录选择不会替换上次成功选择，也不会新增自动扫描。Codex 仅保留可确认仍为本机口径的失败快照，不恢复旧官方账户累计。

`coverage` 逐字段区分 complete / partial / unknown；该标记描述保留数据集的字段覆盖，不证明整个账户历史完整。`detailCoverage` 描述分项使用的数据。旧缓存可读取，缺少覆盖证据则标 unknown。`cacheInputSample` 只累计输入与缓存同时存在、为非负安全整数且缓存不超过输入的记录对。占比使用这批记录的缓存合计 / 输入合计；字段不齐时显示“部分记录”，覆盖率的分母是已知输入，不代表完整账户历史。悬停列出各来源统计分组的覆盖。DeepSeek 按相同时间、模型和脱敏身份组合缓存命中/未命中桶，缺桶不补零。无可用输入或溢出时仍显示“—”；异常不截断到 100%。

## DeepSeek 导入完整性

每次选择目录都是完整快照替换，不与旧目录或旧时间范围合并。扫描到任一无法识别的 CSV、无可用直属 CSV 的 ZIP、结构损坏（未闭合引号、重复表头、行列数不匹配）或无效数据行（时间/模型、已知用量类型的数值/价格、消费金额/币种/钱包缺失或无效）时，整次导入失败。即使其他行有效，也不发布部分统计；保留旧快照、原成功时间与目录，`sync.stale=true`，本次错误通过 POST 和 `lastAttempt` 展示。首次导入失败没有旧快照可保留。

这与字段覆盖不足不同：合法的仅消费、仅请求数或缺 token bucket 导出仍能成功替换，未导出的字段保持未知或明确的已知部分。真正的空目录、只有合法表头的文件允许成功更新为空。现有兼容规则保持：未知用量类型不猜测并提示跳过；仅未知类型、没有任何可用行的导出失败；同 bucket 重复不累计、冲突提示并保留首次值；未知非空钱包仍按 cost 计入；文件名日期无效只忽略声明范围。这些提示本身不等于数据损坏。

行内日期须为真实日历日，汇总日期保留导出时区口径；文件名范围空档用时间数值判断，支持 0000–9999 年边界。成功统计、同步状态与目录在同一 SQLite 事务内写入；任何写入失败会回滚三者并向调用方报错，此时连同步元数据也保持写入前状态。真实 SQLite 触发器故障注入覆盖首次写入、更新及重试，不代表已验证断电、磁盘耗尽或硬件损坏恢复。

## 交互与接口

打开窗口先读缓存，再启动一次同步，最多两个来源并行；刷新窗口及工作区切换不会再次启动。每个来源完成即更新，失败可单独重试。DeepSeek 手动读取，示例工作区不扫描真实数据。

`GET /api/history/dashboard` 在同一 SQLite 读取事务内返回 `total`、`local`、`imported`，只读缓存、禁止 HTTP 缓存、只允许用户会话。示例工作区的 `local` 为空。原有各来源 GET/POST 与 `/api/history/total` 继续兼容。

全部合计仅使用服务端标记 included 的来源。潜在重叠来源不重复计数，但通过来源卡片或「统计口径」的查看操作仍可独立查看。

7/30/90 天与全部只影响趋势图，KPI、模型与来源均为全部历史。缺失日期间保持实线连接，悬停显示没有记录，柱状图不补零，区间合计不加入插值。本机日期使用 UTC，官方和 DeepSeek 使用返回日期。

## 验证范围

`npm run verify:all` 验证统计、权限与服务；`npm run verify:desktop` 使用隔离合成数据验证真实窗口，不默认访问账户。真实账户可用性不能由 fixture 推断。具体来源格式见 [WorkBuddy](08-workbuddy-history.md)、[OpenCode](09-opencode-history.md)、[MiniMax Code](10-minimax-history.md)。
