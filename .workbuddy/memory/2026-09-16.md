### 踩到的坑（详见 docs/01-invariants.md）

1. **`as` 的优先级**：`lcs[i+1][j] as number >= lcs[i][j+1] as number` 会被解析成
   `x as (number >= y)`，剥类型后只剩真值判断。测试用例碰巧两种写法结果相同 → 没抓到；
   是 `tsc` 的 TS2352 抓到的。**结论：typecheck 必须和测试一起跑，两者抓不同的 bug。**
2. **`node:sqlite` 参数绑定**：不接受 `boolean` / `undefined`（直接 TypeError）。适配层统一收敛。
   另外查询返回 **null 原型对象**，`assert.deepEqual` 要先 `{...row}`。
3. **SQLite `BEGIN` 不可嵌套**：`tx()` 必须可重入。服务层天然会嵌套调用
   （seedDemo 里调用 createProposal），单独测每个服务全绿，只有同时走两条路径才炸。
4. **Fastify 空 JSON 体**：带 `content-type: application/json` 但 body 为空会报错并被包成 500。
   需自定义 contentTypeParser 把空体当 `{}`。
5. **Fastify 5.12 起 `disableRequestLogging` 已废弃**，不要加。
6. **进程内 `inject` 测试覆盖不到真实网络**：Cookie 往返、Host 头、静态资源都跳过。
   补了 `scripts/smoke.mjs` 走真实 HTTP，它抓到了上面第 3、4 条。

### 设计稿里那些「哲学」怎么落到代码上

- 未知一律 `null`、绝不用 0 冒充 → schema 里 token 列全部可空 + core 的 `readToken` 只返回 null
- 「只计一次」≠「只存一份」→ `dedupeKey`（批次重放）与 `identityKey`（跨来源同一请求）彻底分开
- 额度是状态不是流水 → 独立表 + `evaluateQuota`，窗口过了没重查就显示「待刷新」
- AI 只能提案 → 仓储层不提供「直接插入 active 记忆」的接口，状态机里没有 candidate
- 「官方文档说支持」≠「已同步」→ 能力四级状态，改成 `verified` 必须同时给证据，否则接口拒绝
